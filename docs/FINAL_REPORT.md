## A. Implementation Report

The seed ships 33 verified components organized in 8 pillars, plus an
immutable core (types, identity, config, constants, base abstractions):

| Pillar                | Components                                                                              |
| --------------------- | -------------------------------------------------------------------------------------- |
| Technical Core        | `core`, `config`, `identity` (immutable)                                                |
| Cognitive             | `reasoning`, `providers`, `context`, `contracts`                                          |
| Memory & Knowledge    | `memory` (MemoryDV), `provenance`, `evidence`                                            |
| Security              | `security`, `firewall`, `policy`, `autonomy`, `approvals`                                |
| Execution             | `execution`, `workflows`, `jobs`, `scheduler`, `resilience`                              |
| Observability          | `observability`, `audit` (normal + tamper-evident), `doctor`, `recovery`                 |
| Integration           | `mcp`, `handoff`, `communication`, `multimodal`, `files`                                 |
| Extensibility         | `tools`, `capabilities`, `skills`, `plugins`                                             |
| Interfaces            | `api`, `cli`                                                                              |

The seed contains **zero domain knowledge**. It only knows HOW to be an
ALBRA agent — not WHAT to do professionally.

### Hard rules enforced in code (and tests)

- DEFAULT-DENY in firewall, policy, permissions, autonomy, audit ACL.
- Autonomy ≠ Permission (both gates checked independently).
- UNKNOWN evidence never auto-promotes to FACT.
- FACT requires `confidence ≥ 0.9` AND `source_type ∈ {tool, external, verified_provider}`.
- Tamper-evident audit separate from normal audit.
- Hash chain detects modification of any historical entry.
- Kill switch is global and overrides explicit ALLOW rules.
- RecoveryManager refuses SECURITY/UNKNOWN auto-recovery + dangerous markers.
- Secrets never appear in logs (redacted at the `_safe_log` boundary).
- Mock provider always available (CORE_ONLY mode fully functional).

## G. Security Report

See **[docs/SECURITY.md](SECURITY.md)** for the full security model.

Highlights:

- **Action Firewall** — DEFAULT-DENY; rule evaluation order
  (kill switch → cooldown → rate limit → rules → deny).
- **Policy Engine** — composes action + actor + risk + permission + context
  + autonomy → decision. ALLOW requires BOTH autonomy AND permission.
- **Autonomy Levels** — L0..L5; Autonomy ≠ Permission; default matrix
  DEFAULT-DENY (unknown action_type → L5 required).
- **HITL Approval Engine** — request / approve / reject / expire / escalate.
  NEVER auto-approves. Tamper-evident evidence chain.
- **Kill Switch** — GLOBAL; audit-logged; post-deactivation cooldown.
- **Secrets Management** — Env / File / Vault backends; never logged
  (`_safe_log` redacts values); two-layer `redact_secret_values()` matcher
  avoids false positives (e.g. `default_max_tokens` not redacted) and
  false negatives (`openai_api_key` always redacted).
- **Tamper-Evident Audit** — SEPARATE from normal audit; SHA-256 hash
  chain (`prev_hash` + `record_hash`); genesis = `SHA-256("")`.
- **Evidence Discipline** — FACT / INFERENCE / ASSUMPTION / UNKNOWN;
  UNKNOWN never auto-promotes (hard rule in `EvidenceContract.promote_to_fact`).
- **Recovery Safety** — `RecoveryManager` refuses SECURITY/UNKNOWN
  auto-recovery + refuses strategies matching dangerous markers
  (`rm_rf`, `delete_database`, `drop_table`, `wipe`, `kill_process`, ...).

## H. Memory Report

See **[docs/MEMORY.md](MEMORY.md)** for the full MemoryDV specification.

Highlights:

- **Five memory types**: EPISODIC, SEMANTIC, FACTUAL, PROCEDURAL, WORKING.
- **Memory isolation**: composite key `(agent_id, domain, user_id, context_id)`
  enforced by `MemoryIsolator` on every write / read.
- **Provenance on every memory write** — `MemoryProvenance.attach()`
  called automatically by `MemoryManager.remember()`.
- **Evidence required for FACT** — `is_fact=True` requires non-empty
  `evidence_ids`; FACT evidence must satisfy `EvidenceContract.validate()`
  (confidence ≥ 0.9 + qualifying source_type).
- **Consolidation policy** — EPISODIC → SEMANTIC when confidence ≥ threshold;
  NEVER promotes UNKNOWN → FACT (hard rule in
  `ConsolidationPolicy.can_promote_to_fact` — always returns False).
- **Backends**: `InMemoryMemoryStore` (default), `SQLiteMemoryStore`
  (stdlib `sqlite3`), `VectorMemoryStore` (lazy `chromadb`).
- **Memory lifecycle**: CREATED → MODIFIED → ACCESSED → CONSOLIDATED →
  ARCHIVED → DELETED → FORGOTTEN. Tracked by `MemoryLifecycle` events.
- **Tombstones** retained on delete (audit traceability).
- **Memory is empty at seed init** — the seed knows nothing.

## I. Provider Report

The seed ships a universal provider stack:

| Class                | Type      | Always Available? | External SDK     | Notes                                     |
| -------------------- | --------- | ----------------- | ---------------- | ----------------------------------------- |
| `MockProvider`       | mock      | YES (CORE_ONLY)   | none             | Deterministic; echoes last user message.  |
| `OpenAIProvider`     | external  | no                | `openai` (lazy)  | Raises clean `NotImplementedError` if missing. |
| `AnthropicProvider`  | external  | no                | `anthropic` (lazy) | Same.                                     |
| `GroqProvider`       | external  | no                | `groq` (lazy)    | Same.                                     |
| `OllamaProvider`     | external  | no                | `ollama` (lazy)  | Local Ollama server; no API key needed.   |
| `ZAIProvider`        | external  | no                | `zai` (lazy)     | Z.AI internal SDK.                        |
| `ProviderRegistry`   | composite | YES               | none             | Always pre-registers Mock.                 |
| `ProviderRouter`     | composite | YES               | none             | Routes with fallback chain; terminates at Mock. |
| `ProviderFallback`   | composite | YES               | none             | Ordered chain; logs every transition.      |
| `ProviderHealth`     | utility   | YES               | none             | Per-provider state machine (HEALTHY / DEGRADED / UNAVAILABLE). |

### Routing

```
LLM request
    ↓
ProviderRouter.route(model)
    ↓
preferred provider (configured + available)
    ↓ (if unavailable)
next available non-mock provider
    ↓ (if all unavailable)
MockProvider (always available, CORE_ONLY safe)
```

### CORE_ONLY invariant

The seed MUST function with zero external credentials. The `MockProvider`
is the always-available fallback. The `ProviderRegistry` pre-registers
Mock at construction; `ProviderRouter.complete()` always terminates at
Mock. There is no "all providers failed" code path that doesn't fall
back to Mock.

To build the first specialized agent (e.g., AGENTE-LEGAL):

1. `git clone https://github.com/ALBRA8/AGENTE-GENERAL.git AGENTE-LEGAL`

   [`docs/SPECIALIZATION.md`](SPECIALIZATION.md)).

4. Re-run `python scripts/clean_room_verify.py` — must still PASS.
5. Add specialization tests under `tests/specialization/`.
6. The specialized agent inherits ALL seed invariants (DEFAULT-DENY,
